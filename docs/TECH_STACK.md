# 筑见项目技术说明（简要）

更新：2026-10-24。本文分两部分：项目**运行时**真正依赖的技术，以及**开发阶段**使用的 AI 工具（MCP、Skill、Agent）。两者不混在一起：部署本项目不需要安装任何 MCP 服务或技能包。

## 一句话结论

- 产品是自研 Web 应用，技术栈为 **React 19 + TypeScript + Vite** 前端、**FastAPI + SQLAlchemy** 后端，开发用 SQLite、部署用 PostgreSQL。
- AI 接入 **3 个百炼模型 + 1 个天气接口**：图像编辑、视觉识别、文本对话、实时天气。
- 产品内**没有自主 Agent**（0 个）；只有 1 个对话助手「小筑」，为单次模型调用 + 规则路由，不做工具循环。
- 业务运行时**不依赖 MCP（0 个）**；开发环境挂载 3 个 MCP 服务，仅用于编码协作。
- 技能包（Skill）全部属于开发工具层，产品运行时不调用。

## 二、已接入的 AI 服务（4 项）

| 能力 | 模型 / 接口 | 调用位置 | 说明 |
| --- | --- | --- | --- |
| 效果图生成、局部改图 | `qwen-image-2.0-pro`，备用 `qwen-image-2.0` | `interior/providers.py` | 多模态接口；可选同地域备用模型，额度耗尽时切换 |
| 户型识别、视觉结构复核 | `qwen3-vl-plus` | `interior/providers.py` | 上传户型图识别房间门窗；生成后可做一次六项检查 |
| 小筑文本对话 | `qwen3.8-27b` | `interior/assistant.py` | 走百炼 OpenAI 兼容接口 `/compatible-mode/v1/chat/completions` |
| 天气查询 | Open-Meteo（geocoding + forecast） | `interior/weather.py` | 免密钥；城市识别、实况与今明预报，失败自动降级 |

模型调用统一受 `ALLOW_AI_CALLS` 控制，使用服务端 `.env` 中的密钥，不暴露到浏览器；文本与视觉调用不扣应用积分，生图按任务结算积分。

## 三、Agent 接入情况

| 类型 | 数量 | 说明 |
| --- | --- | --- |
| 产品内自主 Agent | **0** | 没有“规划—调用工具—再规划”的循环，也没有让模型执行 SQL、改场景或联网搜索的权限 |
| 产品内对话助手 | **1** | 「小筑」：规则意图路由 + 知识检索 + 单次文本模型调用 + 转人工工单 |
| 开发侧子代理类型 | **4** | Explore（代码探索）、general-purpose（通用开发）、Plan（方案规划）、browser_use（浏览器验收） |

「小筑」的定位是助手而不是 Agent：意图、知识、预算、天气与安全判断由确定性代码完成，模型只负责组织语言；模型失败会退回规则回答。涉及结构安全、知识不足或用户主动要求时，转成人工工单。

## 七、边界说明

- 以上“已接入”均指代码中真实存在并可调用的能力，不是规划项。真实调用记录见 [AI_LIVE_VALIDATION.md](AI_LIVE_VALIDATION.md)。
- 天气只播报接口返回的实况与今明预报，不提供气象台预警；城市可识别或使用 `WEATHER_DEFAULT_CITY` 默认值。
- 产品没有支付、MFA、运营后台与向量检索；知识库仍是代码内关键词条目。
- 测试与构建：后端 222 项、前端 103 项、75/75 个接口操作通过；`tsc` 严格类型检查与生产构建通过。
