# 开发约定

1. 场景格式以 `packages/scene/scene.schema.json` 为准。米仅用于 Three.js 展示，传输和数据库统一为整数毫米；金额统一为整数分。
2. `floors` 是实测几何，`layout` 是装修方案。模型图片不写回实测结构。修改结构后必须重新确认，历史版本禁止覆盖。
3. 修改前运行相关测试；几何、权限、积分、导出、任务状态变更必须增加有行为意义的测试。
4. 前端保存通过工作副本修订号进行乐观锁。不要在 409 时自动覆盖；必须保留浏览器草稿并让用户选择。
5. 所有收费任务使用幂等键及冻结/结算账本。任务恢复不可盲目重试已发送的收费服务调用。
6. 凭证只存服务端环境变量，不进入前端构建、日志、版本库或返回 JSON。
7. React/TypeScript 用 Prettier；Python 用 Ruff format。后端静态检查：`ruff check apps/api scripts --select F`。
8. 公共 API 的已实现契约通过 `python scripts/write_openapi.py` 生成。原始开发文档的接口是目标蓝图，不等同于当前实现。
9. 新增数据库字段必须生成并审阅 Alembic 迁移。开发自动建表只能用于全新本地数据库；已有生产库使用迁移。
10. 提交前执行 `scripts/check.ps1`，不提交 `.env`、用户照片、数据库、构建产物和虚拟环境。
