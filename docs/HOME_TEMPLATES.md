## 用户操作

1. 工作台点击“新建项目”，在户型卡片中选择模板，再填写名称创建。卡片提供平面缩略图、净面积、层数及说明。
2. 两层户型通过空间列表上方的楼层按钮切换，房间、门窗、物品列表和 2D 画布随之切换。
3. 在当前楼层录入房间宽、深、层高，拖动家具或编辑精确位置。新物品属于目标房间所在楼层；编辑上层房间不会缩放下层坐标，夹层矮护墙保留独立高度。
4. 3D 提供“本层俯览”“整栋剖面”“房间视角”和“步行漫游”。整栋剖面按楼层真实标高叠放，显示夹层与楼梯；3D 楼层选择器与工作区楼层同步。
5. 第一人称漫游可沿门洞跨房间，并沿有效楼梯连续上下楼。暂停面板提供楼梯下口/上口导航；位置栏显示实际楼层与脚底标高。门控可开关门扇，关门会阻挡通行。
6. 预算包含全项目两层的物品，并显示“楼层 / 房间”。方案比较和只读分享也能切换楼层，3D 可查看整栋剖面。
7. PDF 为每层分别生成平面页，再附全项目家具家电清单；CSV 用楼层与房间标注位置，JSON 保留完整两层数据。新增模板中的通用物品全部待询价。

模板创建后保留“未确认实测”状态。请替换实际尺寸，完成校验，再由用户确认实测。浏览器验收项目也没有伪造实测确认。

## 技术实现

- `apps/api/interior/templates.py` 定义和构造模板。矩形参数使用墙中心线，内轮廓按 200 mm 墙厚内缩 100 mm；共线墙按交点拆段并共享引用，门窗具有房间连接关系。
- `GET /api/home-templates` 提供模板元数据及预览场景。项目创建的 `templateId` 接受11个白名单值，未知值拒绝。模板创建使用深拷贝，不修改其他项目。旧项目可主动使用“重设户型框架”替换当前草稿，可撤销，不改写已保存版本。
- 场景 Schema 增加可选 `floor.stairs`，兼容旧场景；无需数据库迁移。`elevationMm` 为楼层标高，家具 `positionMm[2]` 为本层地面以上的相对高度。
- 楼梯字段为 `id/startMm/endMm/widthMm/targetFloorId/stepCount`。3D 按楼层标高差生成踏步、立板、栏杆与扶手；2D 和 PDF 绘制踏步线。
- 服务端按楼层分别校验房间与家具，拒绝相同标高、错误楼层测量、无效楼梯目标、越界梯段、未进入上层平台的终点，以及占用楼梯的家具。当前最多支持两层。
- 规则布局读取物品所属层的房间、墙洞和障碍物，其他层物品不造成平面投影碰撞；生成方案保持全项目结构哈希。
- `floorScene` 为渲染与漫游提供当前层投影；编辑操作写入完整场景。切换楼层是视图状态，不添加撤销记录、不触发保存。
- CSV 房间重名时不自动选中第一层的同名房间，需要通过对象 ID 或导入界面明确关联。

## 验证与边界

最新完整回归前端61项、后端174项通过，包括11模板的Schema/几何/逐层门洞连通、接口、楼梯及测量楼层、导出与编辑楼层隔离，详见 `VALIDATION.md`。实际模板测试连续双向走完Loft、复式和别墅梯段。

历史浏览器曾验证旧三居室93.76 m²与Loft83.96 m²，旧项目继续保留旧草稿。最新浏览器验证新版别墅305.11 m²、17空间、3.40 m连续上下楼、铺装持久保存和门控。模拟窄屏不代表完成真实手机GPU性能测试。

“楼层与楼梯参数”面板可编辑标高、起终点、宽度、踏步数和目标楼层。尺寸变化造成平台错位时仍需校验调整，不会自动重建结构。直跑梯已支持连续上下楼及自动楼板缺口；尚无任意洞口绘制、转折/螺旋楼梯、结构受力、管线或施工审查能力。
