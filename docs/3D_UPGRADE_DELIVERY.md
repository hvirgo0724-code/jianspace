## 用户操作入口

| 需求 | 入口与操作 |
| --- | --- |
| 使用新版户型 | 工作台“新建项目”；现有项目在空间列表下方点击“重设户型框架”，选择模板、阅读替换提示后应用，可撤销。已保存版本保留。 |
| 走楼梯 | “3D 空间 → 步行漫游”，暂停面板可前往楼梯下口或上口，再开始漫游；WASD/方向键、摇杆与步进按钮共用跨层碰撞。 |
| 开关门 | “门控”面板，或点击 3D 门扇。关闭的门阻挡通行；访客站在关门范围内时拒绝关闭并提示退开。 |
| 更换地面 | 选择房间，在空间属性“地面铺装”中选择；每个房间独立保存，刷新后保留，不改变尺寸。 |
| 添加大窗 | 展开“场景对象与门窗”，选择墙，在属性中添加标准窗、全景大窗、落地窗、平开门或开放通道；有空间才添加，随后校验。 |
| 修改窗型 | 选择已有窗，在洞口属性中选择标准窗、全景大窗或落地玻璃窗，并调整尺寸/窗台高。 |
| 看外观与整栋 | 3D 工具栏“建筑外观 / 整栋剖面 / 本层俯览 / 房间视角”；所有模式可放大。 |
| 平面图生成户型 | 首页“上传户型图”或项目内“上传平面图”；上传 JPEG/PNG/WebP，填写建筑外轮廓总宽与层高，确认识别费用。先查看 2D/3D 草稿、警告，再勾选复核声明载入。 |

旧项目不会被后台自动改写。旧版三居、Loft、复式若保留了不合适的楼梯或房间关系，可使用“重设户型框架”；该操作会替换当前草稿结构与家具，先保存需要保留的设计版本。

## 户型与结构

现在共 **11 种起点**。三室一厅改为客厅/过厅串联私密房间；公共区域之间采用开放通道，卧室与厨卫保留门扇，减少随意穿越卧室的动线。

| 更新模板 | 室内净面积 | 层数 / 空间数 | 附加空间 |
| --- | ---: | --- | --- |
| 三室一厅一卫一厨 | 97.18 m² | 1 / 7 | 过厅 |
| 复式 Loft | 83.96 m² | 2 / 6 | 挑空与夹层 |
| 跃层复式 | 174.38 m² | 2 / 13 | 楼梯井与上层平台 |
| 独栋花园别墅 | 305.11 m² | 2 / 17 | 前庭小院 66.24 m² |
| 小院平层住宅 | 159.38 m² | 1 / 8 | 小院 66.24 m² |

室内净面积排除小院、露台和楼梯井挑空；空间数包含这些空间，不能作为卧室数。别墅楼梯标高 0→3400 mm，Loft 0→2800 mm，复式 0→3000 mm。参考梯段踏面至少 250 mm、单步高度不超过 180 mm；这不是当地建筑规范审查结论。

楼梯改为踏板、立板、钢构支撑、栏杆与扶手。上层楼梯井保留围护墙，移除悬空楼板；上下层楼板/顶面按真实梯段布尔裁切，边缘穿越的洞口转换为缺口，避免把 Three.js 内孔画到外轮廓以外。

院子有独立室外地面、低围墙与花池，不生成室内顶棚；装修估算不为小院计顶面，也不把挑空计地面。外观包含概念坡屋顶与场地底面，复杂轮廓的屋面仍需设计细化。

## 漫游修复

`multiWalk.ts` 以完整多层场景编译导航，保留楼层实际标高；梯段连续计算脚底高度，按垂直范围判断墙、门扇、家具与障碍物。移动拆为最多约 35 mm 子步，禁止从楼梯中段横向离开和站在上层挑空区；无效楼梯目标保持阻挡，等待修正结构。

相机视高为脚底以上 1.60 m。小地图和位置栏显示实际所在楼层、标高及楼梯状态。暂停面板提供楼梯入口，挑空空间不提供漫游落点。门开关只影响当前预览及碰撞，不把访客动作写为设计版本；刷新会恢复初始开门状态。当前支持平开门和无门扇通道，未实现滑轨门动画。

浏览器验证发现并修复了模式切换后的空白渲染与暂停浮层挡住楼梯按钮的问题：各层保持稳定渲染组，减少几何重新挂载，楼层场景投影缓存，取消接触阴影额外渲染通道，仅活动房间使用室内点光源。保留主光阴影、环境光与高清/流畅模式。3D 和 Three.js 运行时分包，避免单个场景包超过 1 MB。

## 平面图识别的处理与边界

1. 图片私有上传、归一化并移除 EXIF。图纸不会作为普通房间照片混在生图参考列表中，查看者无权直接访问原图。
2. 使用已配置的 `DASHSCOPE_VISION_MODEL`，每任务最多一次视觉请求，不自动重试；与生图备用模型链分别处理。需启用 `ALLOW_AI_CALLS=true` 及可用的同地域 Key/Host。
3. 输出最多24个轴对齐矩形房间及100个开口；严格校验 JSON、重复标识、坐标范围、重叠、墙线与开口匹配。不能可靠匹配的开口省略并提示，非法结果不会修改当前草稿。
4. 根据完整图片长宽比及用户总宽统一缩放，墙厚暂用200 mm。最新构建已将两侧半墙厚计入总宽；识别进深、内部分隔和门窗仍可能有误差，需要逐项复核，不能用总宽替代量房。
5. 结果先保存为私有 `recognized_plan` JSON 资产；不会在任务结束时自动替换工作副本。用户预览、确认后载入为未确认草稿，可撤销，保留原有已保存版本。来源和 `unverifiedDimensions` 随草稿保存。

当前支持清晰的单层 PNG/JPEG/WebP，单张≤15 MB。PDF/DWG、弧墙、斜墙、复杂多层图纸、楼梯自动识别与任意 CAD 墙网尚未实现。AI 负责识别结构草稿，程序据此生成尺寸化3D几何；没有接入文本/照片生成任意3D网格、实景扫描或照片级渲染服务。

一次成功识别默认结算 `AI_PLAN_CREDITS=5` 应用积分，另有视觉服务商 token 用量。失败释放应用预留积分；网络超时、取消或异常结果仍可能已产生服务商费用，应核对调用记录，不自动重新付费请求。配置变更需重启 API/worker。

## 实际验收记录

- 自动回归：后端174项、前端61项，严格类型检查及生产构建通过；新增测试直接使用真实 Loft/复式/别墅模板，双向走完梯段，检查挑空支撑、门扇阻挡、不同楼层家具碰撞和楼板裁切。模拟服务商测试与本机真实密钥隔离。
- 桌面浏览器：新版别墅17空间；浅白石材铺装保存后刷新保留；外观/剖面/房间/漫游重复切换无新增控制台错误；门控关闭后按钮切为打开，再恢复。
- 在识别草稿墙面新增2800×2580 mm、离地100 mm的落地窗，属性与模型一致，随后移除临时验收窗并保存。材质切换显式清理木纹法线/粗糙度/AO，屋顶保留投影但不接收自身阴影以消除干扰纹路。
- 实际上楼：`X12.60,Y6.42,Z0.00 → X12.60,Y12.25,Z3.40`，行走约5.8 m。实际下楼：上口`Y12.22,Z3.40 → Y6.28,Z0.00`，约5.9 m。以键盘持续行走完成，未用楼层选择器代替上下楼。
- 真实识别：正常页面上传带“DEMO FLOOR PLAN - NOT A REAL HOUSE”的合成图，总宽8000 mm、层高2800 mm；`qwen3-vl-plus` 一次调用识别2房间/3开口，1344 tokens。应用积分90→85，冻结归零，一笔reserve和一笔charge，未重复请求。
- 识别完成、用户载入前，原工作副本仍为1房间；载入后为2房间且保留draft状态，几何校验通过。该首次真实结果存在进深约6.4%的识别偏差；随后增加的外轮廓半墙厚校正通过自动测试，未为此重复收费识别。
- 393×852模拟视口检查识别面板，页面无横向溢出。未替代真实手机GPU、触屏多指、低内存设备与大规模复杂户型的性能验收。
