# 小筑 · 家装智能助手设计

更新：2026-10-24。本文说明助手的产品定位、能力边界、平台集成方式与转人工流程；实现以源码与测试为准。

## 名称与定位

**小筑**，取“筑见”的“筑”字，短、好叫、有家的意味。完整称呼为“小筑 · 家装管家”。候选名还有“筑小间”“间管家”，最终选“小筑”是因为它在聊天里最自然，也方便出现在按钮、工单和提示语中。

小筑不是全屋设计师，也不是施工监理。它先负责四件事：把装修知识讲清楚、把预算讲成区间、把设计问题拆成可执行步骤、在不确定时把人叫来。装修之外也能聊几句日常，天气走实时接口，其余交给文本模型。

## 能力边界

| 能做 | 不做 |
| --- | --- |
| 通用装修知识、材料、工艺、验收节点 | 不判定承重墙、燃气、消防与结构安全 |
| 基于当前项目面积与状态的预算区间 | 不承诺精确报价、不编造品牌价格 |
| 风格、配色、灯光、收纳的一般建议 | 不替代设计师出图或承诺施工效果 |
| 按城市查询当前天气与今明两天温度 | 不提供气象台预警，也不编造实时数据 |
| 生活常识、饮食方向、日常寒暄（由文本模型回答） | 不编造具体店铺、营业信息或新闻事实 |
| 把知识不足、纠纷、投诉转成人工工单 | 不自动修改项目几何、不代替用户确认尺寸 |

装修问题先检索知识库再作答；天气由 Open-Meteo 实时数据生成，不交给模型改写；非装修问题直接使用文本模型，但保留“不编造实时数据”的约束。回答只给区间与影响因素；涉及结构改造时明确拒绝建议并提示转人工。知识条目都带来源说明。

## 架构

```text
用户消息
  ├─ 意图路由（规则评分）── 转人工 / 预算 / 施工 / 设计 / 知识 / 天气 / 寒暄 / 日常
  ├─ 平台上下文（项目面积、空间数、确认状态、照片数）
  ├─ 装修相关：关键词检索知识库，条目随模型上下文注入
  ├─ 天气：城市识别 → Open-Meteo 地理编码 + 实时/今明预报（失败降级为提示）
  ├─ 非装修：文本模型按通用闲聊模式回答
  ├─ 工具：预算区间、下一步导航、转人工
  ├─ 可选文本模型叙述（未配置或失败时自动退回规则回答）
  └─ 对话落库（conversation + message，含意图、来源、动作、模式）
```

- **规则优先**：意图、知识检索、预算、天气与安全判断由确定性代码完成，测试可覆盖、不产生模型费用。
- **模型可选**：配置 `DASHSCOPE_TEXT_MODEL` 后才调用文本模型；调用失败、超时或返回空内容时自动退回规则回答，不会把失败伪装成成功。
- **按问题分流**：装修问题注入知识条目并优先依据；非装修问题不再套用“只能用知识库”的约束，但模型仍不得编造实时数据、价格与结构安全结论。

## 与筑见平台的配合

- **工作台**：右下角“小筑”浮窗，携带当前 `projectId`；后端只用当前用户有权访问的工作副本计算面积与状态。
- **动作联动**：回答里的“打开预算清单”“进入空间设计”“查看功能与流程”直接切换到对应页签，不只能聊天。
- **预算**：项目已录入面积时直接使用实测面积；未录入时从问题中识别“89 平”等面积，只给半包/全包区间。
- **权限**：查看者也可聊天，但项目上下文来自其可读副本；对话与工单只能本人读取。
- **未登录**：不显示助手入口；全局助手只出现在工作台，不读取任何项目数据。
- **隐私**：对话不包含原始照片内容；工单只附文字记录、项目名称与联系方式。

## 转人工

触发条件：
1. 用户明确说“人工/投诉/纠纷/退款”。
2. 装修问题知识检索为空、或回答被判定不可靠。
3. 涉及承重墙、燃气、消防等结构安全。
4. 用户在任何回答后点击“转人工顾问”。
5. 未配置文本模型时，非装修问题无法回答，也会提示转人工。

流程：
1. 用户填写问题类型、联系方式与说明；系统创建工单，状态 `pending`。
2. 工单快照最近 20 条对话、项目 ID 与用户信息；若配置 `SUPPORT_EMAIL` 且 SMTP 可用，向支持邮箱发送通知（失败不阻断工单）。
3. 运维通过 `scripts/handoffs.py` 或管理员 API 查看队列；回复会以“【人工客服】”消息写回对话，用户下次打开小筑即可看到。
4. 用户可在转人工弹窗查看自己的历史工单与处理结果。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/assistant/chat` | 发送消息，返回会话 ID、意图、来源、动作、模式 |
| GET | `/api/assistant/conversations/{id}` | 读取本人会话历史 |
| POST | `/api/assistant/handoffs` | 创建转人工工单 |
| GET | `/api/assistant/handoffs` | 本人最近工单 |
| GET | `/api/admin/assistant/handoffs` | 管理员工单队列 |
| PATCH | `/api/admin/assistant/handoffs/{id}` | 管理员更新状态与回复 |

## 配置

```env
# 可选：填写后启用文本模型；留空则只用规则知识库
# 当前本地配置：qwen3.8-27b（通过百炼 OpenAI 兼容接口调用）
DASHSCOPE_TEXT_MODEL=qwen3.8-27b
# 小筑天气查询：Open-Meteo 免费接口，不需要密钥
WEATHER_ENABLED=true
# 未在问题中指定城市时使用；留空则反问城市
WEATHER_DEFAULT_CITY=上海
# 可选：转人工通知邮箱；SMTP 未配置时只保存工单
SUPPORT_EMAIL=
```

文本模型与生图共用 `DASHSCOPE_API_KEY`、`DASHSCOPE_API_BASE` 和 `ALLOW_AI_CALLS`。助手文本调用走 `{API_BASE}/compatible-mode/v1/chat/completions`，而原生 `/api/v1/services/aigc/text-generation/generation` 对 `qwen3.8-27b` 返回 URL 错误，因此不要混用两套协议。文本调用产生服务商 token 用量，不扣应用积分。

天气使用 Open-Meteo 的 `geocoding-api` 与 `api.open-meteo.com`，无需密钥，也不受 `ALLOW_AI_CALLS` 控制；可用 `WEATHER_API_BASE`、`WEATHER_GEOCODING_BASE` 指向代理，用 `WEATHER_TIMEOUT_SECONDS` 调整超时。服务不可达时只返回提示，不影响其他问答。

## 安全与失败策略

- 结构安全：拒绝拆除建议，要求物业与结构工程师复核，并建议转人工。
- 价格：只给区间，标注“非报价”，不编造品牌与地区价格。
- 天气：只播报接口返回的实况与今明预报，不生成预警；城市识别失败时反问，接口失败时明确说明。
- 闲聊：非装修问题交给文本模型，但不允许编造实时数据、具体店铺营业信息或新闻；模型失败时退回“转人工”提示。
- 提示注入：用户消息视为不可信输入；助手没有执行 SQL、写入项目或任意网络请求的工具，天气只访问固定接口。
- 失败：模型不可用时返回规则答案并标注“知识库模式”；规则也答不了时明确说不知道并转人工。
- 限流：聊天 60 次/5 分钟/IP，工单 5 次/小时/IP。

## 当前实现与后续

已实现：规则意图路由、9 类知识条目、项目上下文、预算区间、导航动作、可选文本模型、按装修/非装修分流提示词、天气实时查询、会话落库、转人工工单、管理员队列/回复、运维 CLI、桌面与窄屏浮窗。

后续建议：
1. 将知识库换成可维护的文档集合与向量检索（当前为代码内关键词条目）。
2. 增加管理员工单页面与工单状态通知，而不是只靠 CLI。
3. 接入真实客服系统（企业微信/飞书）或邮件会话，而不是单向下发。
4. 为文本模型增加按用户/项目的预算上限与调用审计。
