## 使用方式

1. 在“空间设计”选择目标房间，再从“家具与家电”选择分类或输入关键词。分类和搜索同时生效；例如选择家电再搜索“空调”会出现 2 款。支持名称及预设英文关键词，不依赖外部搜索服务。
2. 点击卡片加入房间，卡片尺寸顺序为宽×深×高，单位 mm。每个实例独立保存，修改一台设备不会改变目录或其他实例。
3. 在 2D 中拖动与旋转；在属性中编辑 X、Y、Z、宽、深、高。Z 表示物品底部离楼面的高度，组合柜、梳妆台等尺寸包含其镜面或龙头的最高点。
4. 切换 3D 检查造型、位置与比例，也可使用现有第一人称漫游。修改尺寸后保留模型类型。
5. 完成摆放后运行“校验场景”。台面物品仍需手动放到合适的柜面；模型不会自动接通水、电、燃气或识别承重支撑。
6. 在预算中填写实际报价。未填价格显示“待询价”，不按免费商品计入已知金额。PDF、CSV 和 JSON 使用同一份场景数据。

## 初始放置

| 放置方式 | 默认规则 |
| --- | --- |
| 落地 | 底部 Z=0；初始位于房间外接矩形中心，需按户型检查并移动 |
| 壁挂空调 | Z=1950 mm，尝试放在可容纳宽度的房间内侧墙边，并朝向室内 |
| 壁挂抽油烟机 | Z=1500 mm，采用相同的墙边初始放置规则 |
| 微波炉、燃气灶 | Z=850 mm，用户调整到实际台面位置与高度 |
| 床头台灯 | Z=500 mm，用户调整到实际床头柜位置与高度 |

初始高度会按层高和物品高度限制，避免默认顶部超出房间；物品本身过高、房间过小、凹形轮廓或无合适墙边时仍须手动处理并校验。墙边算法不自动避开全部门窗或其他物品。默认高度只是编辑起点，不是安装规范。

服务端家具相交校验同时检查平面和竖向区间。门扇校验也检查高度，位于门洞上方的设备不会仅因平面投影相交而被误判为挡门。

## 模型与数据实现

- 共用目录：`packages/catalog/items.json`，后端 `catalog.py` 读取此文件；前端以接口结果显示目录，测试直接读取同一份数据。没有新增接口或数据库迁移。
- 每条数据包含稳定 ID、名称、分组、模型类型、毫米尺寸、默认 Z、放置方式、关键词和可空价格。当前 48 条价格均为空。
- 添加实例时把模型类型写入场景快照的 `modelAssetId`，格式为 `builtin-类型`；该值由模型白名单解析，不作为外部资源 URL。旧场景没有此值时继续按名称识别模型。
- `BuiltinModels.tsx` 提供新增参数模型：冰箱门与把手、滚筒舱门、面板、空调出风口、灶台、龙头、镜面、淋浴玻璃、灯罩和植株等细节。原有授权模型及其署名继续保留。
- 新增模型使用本地代码几何和共享材质，未增加远程模型请求或 npm 依赖。搪瓷、金属、陶瓷、玻璃、屏幕、叶片等材质随现有配色处理。
- `geometryBounds.ts` 在模型局部坐标测量包围盒，`ModelBounds.tsx` 归一化尺寸，再由家具实例的实际宽深高缩放；父节点的平移、旋转和缩放不会污染测量。
- 属性编辑保留模型类型；自动保存成功后同时更新工作副本查询缓存，离开再返回项目会使用最新保存内容。

这些模型用于通用外观和占位参考，不对应具体品牌商品的开门方向、内部机构、安装孔位或完整曲面细节。新增物品的尺寸以当前目录或用户录入值为准，名称中的英寸和容量描述不替代商品实测规格。
