# 第一人称房间漫游

最新回归已检查门控和 0→3.40→0 m 连续上下楼，并修复俯览时墙门被压低的问题。俯览仅透明前侧外墙，漫游保持完整墙高、原门窗尺寸和同源碰撞；详见 [完整功能验收](FULL_REGRESSION.md)。

更新：2026-10-23。最新支持连续楼梯上下层、门控与真实标高导航，见 [3D_UPGRADE_DELIVERY.md](3D_UPGRADE_DELIVERY.md)。保留全屋俯览、房间环绕和2D编辑。

## 进入与操作

在项目的「空间设计 → 3D 空间」选择「步行漫游」，点击「开始漫游」。电脑可点击右上角放大图标；手机窄屏进入漫游时自动放大，右上角可以还原。

| 设备 / 控件 | 操作 |
| --- | --- |
| 电脑键盘 | W / ↑ 前进，S / ↓ 后退，A / ← 左移，D / → 右移。开始或点击画面后获得键盘焦点；编辑输入框时不会截获行走按键。 |
| 鼠标 / 手指 | 在场景中按住并拖动，水平环顾或上下观察。无需锁定鼠标、定位、摄像头或陀螺仪权限。 |
| 左下摇杆 | 向前后左右拖动；偏移量决定移动强度。松开、取消触摸或页面失焦后停止。移动与观察使用独立指针状态，可供双手操作。 |
| 四个方向按钮 | 每次请求约 0.35 m 的平滑步进，经过相同碰撞检查。快速点击的待行走距离限制为 0.7 m，避免排队过长。 |
| 转身按钮 | 每次左 / 右转 30°，不改变位置。 |
| 房间选择 | 快速前往该房间中的安全落点；也可以沿实际门洞步行过去。 |
| 小地图 | 显示房间、家具占地、当前位置与朝向，支持收起；房间名和行走距离随位置更新。 |
| 暂停 / Esc | 停止移动并显示继续入口。标签页隐藏或窗口失焦也会暂停，防止按键未释放时继续行走。 |
| 重置 / 退出 | 重置返回所选房间的安全起点；全屋俯览或退出按钮恢复观察模式。 |

漫游视高为 1.60 m，视场角为 70°，水平步行速度最高约 1.25 m/s。视线俯仰受限，行走保持地面高度，不会因向上观察而飞起。

## 建筑和室内细节

- 漫游时保留整层全部房间、家具、完整墙高与房间顶面，能够透过门洞看到相邻空间。
- 顶面添加通用吸顶灯外形和发光面；按房间轮廓寻找内部安装点，避免 L 形房间的灯具落在外部。灯具属于效果参考，不是用户选定商品或照明工程计算结果。
- 顶角线与踢脚线按房间在墙段上的范围裁剪，避免一条外墙被多房间引用时出现重叠饰条。
- 门扇增加饰面和双面把手，窗户补充把手。点击门扇或“门控”按钮在关闭与90°展开间切换，渲染和导航共用同一套姿态；状态保留到本次预览结束，刷新恢复初始状态。
- 门窗尺寸、房屋结构、家具尺寸、原有门扇开向和设计历史不会因漫游动作而改变，也不会生成新的保存版本。

## 导航与碰撞

实现文件位于 `apps/web/src/components/visuals/`：

| 文件 | 职责 |
| --- | --- |
| `walkMath.ts` | 从实测场景编译行走区域与碰撞多边形；安全落点、移动子步、沿墙滑动及相机方向换算。 |
| `multiWalk.ts` | 多层导航、连续梯段高度、挑空支撑、垂直碰撞与跨层移动。 |
| `WalkControls.tsx` | 相机、键盘与指针输入、平滑步进、暂停清理、按需请求渲染和位置反馈。 |
| `WalkHUD.tsx` | 操作说明、触屏摇杆、步进 / 转身按钮、当前房间、朝向小地图。 |
| `sceneMath.ts` | 渲染与碰撞共用的门扇姿态、室内参考相机与灯具位置。 |
| `Architecture3D.tsx` | 全层建筑、真实洞口、顶面、通用灯具、饰条与门窗细节。 |
| `Scene3D.tsx` | 三种观察模式切换、放大布局、导航资源装配、原编辑器联动。 |

场景仍以整数毫米存储。导航平面使用场景X/Y米，Three.js相机使用`[x, 脚底标高+1.6, -y]`。访客采用半径0.18 m占地与1.72 m通行净高。

1. 房间轮廓组成可行走地面；连接两个现有房间且有足够净高的门洞补齐墙厚内的地面通道。
2. 墙体在有效门洞处切开，并计入门框净宽、门扇展开后的占地。窗户不作为通道；外门不会允许用户走出当前房屋地面。
3. 家具按录入的宽深和旋转生成占地多边形。柱体等固定设施按原轮廓检查；高于人体的悬空设施不阻挡地面步行。
4. 跨层移动拆成不超过35 mm子步，受阻时尝试滑动；楼梯中段不能横向离开，不能站到上层挑空内，无效梯段保持阻挡。
5. 在边界处检查圆周 16 个支撑点和中心，处理凹形地面与缺少墙体的导入轮廓。碰撞障碍使用圆到多边形边的距离检测。
6. 先尝试保存的室内相机位置，再搜索有净空的落点。房间被家具占满或层高不足时禁用开始按钮并给出说明。

该算法用于视觉导航，不等同于建筑无障碍、消防疏散或人体工学规范验收；它也不自动优化布局或计算通行路径评分。家具碰撞采用保守占地，因此不会钻入桌下或穿过沙发模型空隙。

## 性能和状态

- 沿用按需渲染：持续按键、摇杆和未完成步进才续请求帧；静止时不保持常驻动画循环。
- 单帧时间步最高取 50 ms，并继续执行碰撞子步；对角线归一化，避免斜向加速。
- HUD 常规位置反馈约每 120 ms 更新一次，停止时补发最终位置，避免界面抖动和显示滞后。
- 建筑与家具组件记忆化，导航位置不写入场景；碰撞数据只在房间 / 墙体 / 门窗 / 家具变化时重建。
- 模型和贴图继续使用本地缓存；高清 / 流畅档位适用于漫游。当前没有实测手机 GPU 帧率或承诺固定帧率。
- 不使用持续指针锁或设备位置权限。手机窄屏使用页面内放大视图，非浏览器原生全屏 API。

## 验证

前端共 25 项测试通过，本轮新增 12 项导航行为测试，覆盖跨房间门洞与墙厚、阻墙 / 滑动 / 大步长防穿墙、外门与窗户边界、窄门低门、斜放家具、柱体 / 悬空梁、无安全落点、L 形地面、对角线归一化、门扇一致性与角点净空。TypeScript 严格检查与生产构建通过。

桌面浏览器实际检查了键盘 W 行走、拖动环顾 / 俯视、步进与转身、靠近床时滑动受阻、Esc 暂停，以及从客厅绕门扇走入卧室的完整过程。393×852 模拟视口检查了自动放大、房间跳转、摇杆移动及观察；未以真实手机验证多点触摸和 GPU 性能。

## 当前边界

这是尺寸化三维模型的自由漫游，支持两层住宅直跑楼梯连续上下；尚无跳跃、攀爬或VR。未接入高德地图，也没有从普通照片重建连续全景、摄影测量网格或3D Gaussian Splatting，当前为实时渲染装修参考。
